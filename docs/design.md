# Orbit 设计文档

> 状态：概念设计已闭环，待进入实现阶段。

## 0. 问题定义

AI 陪伴产品的核心痛点是**上下文贫瘠**：

1. 记忆只有"聊天记录"一种来源，天然线性、琐碎、会截断；
2. 角色没有"后台生活"——真人会活在自己的日常里并把见闻带进对话，AI 没有，只能反复翻炒已有对话；
3. 上下文装不下时靠摘要/向量检索回填，倾向于反复捞回同几段高显著性记忆，导致车轱辘话。

Orbit 的解法：不是把已有对话记得更牢，而是**让角色持续产生新的生活素材**。两个支柱：

- **引导式人设共建**：深度、独特、结构化的人设档案；
- **模拟世界系统**：主角与 4 个 NPC 持续运转的世界，源源不断产出对话素材。

## 1. 已确认的核心决策

| 决策点 | 结论 |
|---|---|
| 时间模型 | 虚拟时间与真实时间**对称**，但**允许暂停世界** |
| 缺席反应 | 用户三天不上线时主角如何反应，交给用户决策（见 §4） |
| 玩家指令 | GodView **不接受**玩家指令，用户只能通过对话以角色身份影响世界 |
| 用户规模 | **单用户**（v1 严格限定，避免一致性复杂度爆炸） |
| 产品形态 | **独立 App**（完整掌控上下文，排除外部记忆/人设干扰；解锁主动消息推送） |
| 模型来源 | **BYOK**（用户自备 API Key） |
| NPC 数量 | **4 个** |

## 2. 人设向导：引导式共建

原则：**不是 AI 一次性生成，也不是用户一次全写完**。每个回答都是用户做的一次选择，选择产生独特性——这是对抗"AI 平均脸"的核心机制。

### 2.1 探索维度与顺序

1. **锚点层**：名字、性别、年龄、外貌关键词
2. **气质层**：用情境选择题（"遇到烦心事 TA 更可能：倾诉/闷着/阴阳怪气"），行为倾向优于平面形容词
3. **语言习惯**：口头禅、打字习惯（长短句、标点、emoji 频率、已读乱回）——对聊天真实感的贡献远超性格描述
4. **价值观与边界**：亲密关系观、金钱观、雷区、底线
5. **缺陷与矛盾**（最关键也最易被忽略）：完美人设三天就腻，矛盾感是"像人"的核心
6. **过去**：成长背景、一两件"深夜会突然想起"级别的关键经历
7. **日常结构**：作息、职业、最近在忙/烦什么——接入世界系统的接口
8. **你们的关系**：主角与用户的关系起点（旧友/初识/青梅竹马…）、称呼

### 2.2 交互机制

- **混合主动权**：每一步提供"我来写 / 你提议我改 / 你替我定"三档，防 interrogation fatigue
- **AI 先提议、用户选择/修改**：每章 AI 基于已有答案给 2~3 个提议，用户选一个、改一改或完全自己写
- **示例对话 > 形容词列表**：向导末尾产出 3~5 段"典型对话片段"，风格约束力强于任何性格描述（这也是蒸馏 SKILL 的核心价值）

### 2.3 数据原则

- 人设必须是**结构化数据**，不是散文——才能被世界系统查询和演化
- 第一天就区分**静态人设**（profile）与**动态状态**（state：心情、精力、正在烦的事、对各人好感度），后者被模拟持续改写

### 2.4 向导流程

```
第一章 锚点      名字、性别、年龄、外貌关键词
第二章 气质      5~8 道情境选择题（行为倾向而非形容词）
第三章 声音      口头禅、打字习惯、emoji 风格 → AI 生成 3 段示例对话，用户挑/改
第四章 内核      价值观、雷区、缺陷与矛盾、一件难忘的往事
第五章 生活      身份（职员/学生/…）、作息、最近在忙什么烦什么
第六章 世界      逐个速写 4 个 NPC（名字/关系/一句话性格/一个秘密）
               + NPC 之间的关系一句话
第七章 你们      主角和用户的关系起点、称呼
收尾            AI 生成完整人设卡供总览，用户确认或回改 → 世界点火
```

## 3. 人设的快速来源（可选入口）

向导之外支持两条捷径：

- **现成人物 SKILL / 蒸馏 SKILL**：直接导入作为人设基础；
- **已有数据蒸馏**：从已有素材中提炼人设。

导入后仍可向导式补完和修改。

## 4. 时间与缺席策略

### 4.1 运行模式

- **运转中**：虚拟时间=真实时间。主角有作息——凌晨三点来消息 TA 可能在睡觉（慢回、迷糊），午休在工位偷偷回你
- **暂停**：世界时钟冻结，用户回来时"上一秒你还在"

### 4.2 缺席策略：用户定规则，人设定表达

设置项是底层的"我不在时世界继续转还是暂停"，**不是**"主角会不会苦等"这种直白选项。世界继续转时主角有多在意，交给性格自然演绎：

- 黏人型：委屈、胡思乱想、一上线连发好几条
- 独立型：过了三天自己的生活，回来分享，但有一点点疏远
- 回避型：明明在意却装没事，要用户去撬开

### 4.3 快进分层

世界继续转 N 天后用户回来，快进摘要按天压缩（每天 1~3 条关键事件），只有**涉及用户的开放线索推进**才做深度推演，控制成本。

## 5. 用户与世界的边界

- ❌ 用户不能命令 GodView（"让他俩和好吧" → 无效）
- ✅ 用户可以在**对话里**影响世界（"我觉得你该跟 Celina 谈谈" → 主角可能听、不听、或赌气反着来）

前者破坏世界自主性；后者恰恰是世界的意义——用户通过角色关系施加影响，聊天因此有了重量。

## 6. 世界模拟系统

### 6.1 时间模型：事件驱动 + 惰性快进

- 不实时空跑模拟（烧钱且没人看）
- 用户回来时，GodView 计算距上次会话的时长，快进生成世界事件摘要
- BYOK + local-first 架构下，v1 采用纯**打开 App 时快进**，最简单也最诚实

### 6.2 成本分层

- 日常事件（上班、吃饭、闲聊）：模板 + 小模型，只产出世界日志条目
- 重要事件（吵架、告白、失业、生病）：完整多 agent 推演
- 用户在场的主角对话用最强模型
- GodView 是唯一常驻的"聪明人"，NPC 按需实例化

### 6.3 GodView 职责

- 世界时钟与调度（滴答、快进）
- 全局一致性：主角不能同时在两地，NPC 时间线不矛盾
- **信息不对称管理**：每条信息有"谁知道"的知情人集合，八卦和秘密因此成立
- 节奏控制：戏剧曲线，不能天天高潮也不能全是流水账
- 外部世界注入：天气、节日、季节、大环境事件
- **主动消息决策**：决定主角什么时候主动开口

### 6.4 事件系统

- 事件类型：日常 / 关系 / 外部 / 里程碑
- 每个事件写入：参与者记忆、关系状态变化、可能产生**开放线索（open loops）**
- **开放线索是反复读的核武器**："主角明天要面试很紧张"——线索悬着，第二天自然有话可说。世界永远欠着几个未完的线头，对话就永远有水源

### 6.5 单一事实源

全局世界日志（WorldLog）是唯一 ground truth。每个 agent 的记忆 = 日志按知情权过滤的视图 + 私密内心活动。调试世界 bug 只查一张表。

### 6.6 对话上下文组装

喂给主角对话的上下文：

```
人设核心 + 语言习惯 + 示例对话片段
+ 主角对用户的记忆与印象（用户模型）
+ 近期世界事件（主角视角过滤后）
+ 未完结线索
+ 当前状态（心情 / 在干嘛 / 几点了）
```

**主角只能访问自己视角的素材**——GodView 知道的阴谋，主角不知道。

### 6.7 主动消息

独立 App 的核心红利。触发点来自世界事件：

- 开放线索推进（"面试完了！！！"）
- 世界事件波及情绪（想找人吐槽）
- 纯日常（午休拍个午餐图）

护栏：频率上限（每天 N 次，可调）+ 静默时段（默认深夜不打扰，夜猫子人设可放开）。

## 7. NPC 设计（4 个）

4 个 = 4 条主角边 + 6 条 NPC 间边，共 10 条关系边，足以产生八卦传播，一致性仍可控。

- **生态位区分**（默认提议，用户可改）：1 密友（情感话题）+ 1 同事/同学（日常环境）+ 1 家人（背景与责任）+ 1 张力角色（暧昧/死对头/前任，戏剧话题）
- **NPC 走 30 秒速写**，不走完整向导：名字、与主角关系、一句话性格、**一个秘密或执念**（世界戏剧性的初始燃料），其余由 GodView 在模拟中补完并沉淀回档案
- NPC 之间的关系边在创建时一句带过，它们是世界事件的放大器

## 8. BYOK 的架构推论

1. **模型分层开放配置**：主力模型（主角对话，吃质量）与勤务模型（滴答/摘要/NPC 日常，吃便宜）分别配置端点
2. **世界活跃度档位**：安静（每天 1 次滴答）/ 普通 / 热闹，配 token 用量仪表盘与月度预算上限（超额自动降档）——BYOK 用户最怕后台偷跑 token，透明是信任的前提
3. **local-first**：数据存本地、API 直连用户端点、零服务器成本、"所有数据不出设备"是陪伴类产品的杀手级隐私卖点

## 9. 主角的用户模型

主角持续沉淀对用户的认知：用户事实库、习惯、印象变化、关系阶段。世界线（TA 的生活）与关系线（你们之间）是两条并行的演化线——没有这层，世界再丰富，关系本身是静态的。

## 10. 核心数据模型（第一版）

```
Protagonist（主角）
├─ profile      静态人设：锚点/气质倾向/语言习惯/价值观/缺陷矛盾/过去/示例对话
├─ state        动态状态：当前心情、精力、正在做的事、正在烦的事
├─ userModel    对用户的认知：用户事实库、印象、关系阶段、内部称呼
└─ schedule     作息模板：工作日/周末的典型日程骨架

NPC × 4
├─ profile      轻量人设：名字、与主角关系、性格速写、秘密/执念
├─ state        动态状态（比主角简化一档）
└─ relations    与主角 + 与其他 NPC 的关系边（性质、温度、近期变化）

WorldLog       世界日志：事件时间线（唯一事实源）
               每条事件：时间、参与者、类型、知情者集合、后果、生成的线索

OpenLoops      未完结线索：内容、涉及谁、预期推进时间、状态

Settings       世界模式（运转/暂停）、缺席策略、活跃度档位、
               模型端点×2、预算上限、静默时段
```

## 11. 架构总览

```
┌─ 客户端（聊天 UI / 向导 UI / 推送接收）
│
├─ 对话引擎：组装上下文 → 生成回复
│
├─ 世界引擎：时钟 / 滴答 / 快进 / GodView
│    事件生成（分级）、信息不对称、主动消息决策
│
├─ 人设向导：引导式共建 → 结构化人设档案
│
└─ 世界日志：全局唯一事实源（时间线）
```

## 12. 路线图

### v1（MVP）
- 人设向导（完整七章）
- 对话引擎（含用户模型）
- 简化世界：4 个 NPC 档案就绪，每天一次模板化滴答，主角视角摘要喂入对话
- 主动消息
- 暂停/缺席策略
- BYOK 双层模型配置 + 用量仪表盘

### v2
- 完整多 agent 事件推演
- 秘密与信息不对称完整实现
- 关系线自动演化
- GodView 节奏控制（戏剧曲线）
- 世界活跃度档位全开
