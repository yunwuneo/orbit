# 事件后续链真实验收记录

验收日期：2026-10-16（Asia/Shanghai）。结论：**虚构隔离区中的真实模型与 Notion 链路通过本次边界内验收；生产启用、部署和长期运行未验收。**本报告只记录脱敏后的选择、计数、时间与回执结果，不包含凭据或完整提示词。

## 范围与结果

在配置的 Echo 运行区下建立了带标记的隔离测试根、虚构事件/计划/记忆数据源及事项数据源。所有模型输入均为明确标注的虚构邀请、补充和书单活动；没有写入正式故事事件、状态或记忆，没有启动常驻服务。

真实模型与远端读回验证了以下链路：

| 场景 | 远端观察 |
| --- | --- |
| 虚构出游邀请 | Echo 自主追问日期和地点；原邀请中未知项保持不变 |
| 人工后续补充 | Echo 再次追问未确定的日期和地点；新补充通过“前序事件”关联原事项 |
| 书单活动邀请 | Echo 自主接受可选的短计划；计划时间按上海时区解释 |
| 到期计划复评 | Echo 选择现在执行；独立执行结果与决定分别写入，计划更新为已完成 |
| 后续世界检查 | 返回 `no_event`，没有生成虚假外部事件 |
| 丢失写入响应 | 在真实创建提交后注入一次响应丢失；重开本地状态后通过稳定标记找回原页，没有重复创建 |

书单计划原定上海时间 17:46 开始。验收在稍后恢复时已过该时刻，Echo 基于当时当前窗口选择“现在执行”，独立结果记录在 23:43 左右；Orbit 没有把过期计划自动标记完成。随后约 23:45 的世界检查返回 `no_event`。

Notion 远端审计通过：事件 8 条、计划 1 条、事项 2 条；事项节点各 4 条、修订分别为 4 和 3；11 个稳定写入标记均唯一。所有节点回执指纹、完整发生时间、所属事项、节点类型、父子关系及事项进度均已读回核对；未核对写入为 0。临时根随后已归档并通过远端读取确认归档状态：[隔离验收区](https://www.notion.so/3fb22e543e5881c09a7ae408c51cbeeb)。

本地回归共 98 项通过。真实联调期间修复并回归了 Notion 日期 API 序列化差异、旧投影回执不能清除更新的恢复计划、人工补充的隐含因果边需补写到远端，以及模型调用耗时后应以实际生成时刻记录节点和后续检查时间等问题。前序判断中协议字段/父节点不一致的结果曾被拒绝，之后在安全重试中恢复；未把无效输出写入故事。

## 边界

此结果证明本次隔离数据、当前配置模型和 Notion API 路径的有限真实链路可工作，不证明模型在所有情境中的长期角色稳定性，也不覆盖全部计划分支、全部网络/回执故障组合、长时间停机、多事项长期负载、Linux/systemd、日本云服务器或生产结构初始化。Notion 读后写之间仍存在 API 不提供原子 CAS 的并发窗口。正式 `[continuation]` 仍默认关闭，未修改正式 Notion 内容，未部署或启动生产服务。
